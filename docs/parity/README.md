# Feature Parity Validation System

Automated feature detection and parity tracking across all 6 Agenkit language implementations.

## Quick Start

```bash
# Scan all languages and generate reports
python scripts/parity/feature_scanner.py
python scripts/parity/matrix_generator.py

# Check for regressions (used in CI)
python scripts/parity/check_regression.py

# Run parity tests
pytest tests/parity/ -v
```

## Overview

The parity validation system automatically:

1. **Detects Features**: Scans all 6 codebases (Python, Go, TypeScript, Rust, C++, Zig)
2. **Generates Reports**: Creates visual parity matrix and gap analysis
3. **Prevents Regressions**: CI validation ensures features don't disappear
4. **Tracks Progress**: Historical view of parity improvements

## Architecture

### Scanners

Language-specific scanners use AST parsing (Python) or regex (others) to detect features:

- **Python Scanner** (`scripts/parity/scanners/python_scanner.py`)
  - Uses AST parsing for highest accuracy
  - Detects: patterns, middleware, LLM adapters, memory backends

- **Go Scanner** (`scripts/parity/scanners/go_scanner.py`)
  - Regex-based: `type FooAgent struct`
  - Filters out mocks and internal types

- **TypeScript Scanner** (`scripts/parity/scanners/typescript_scanner.py`)
  - Regex-based: `class FooAgent`
  - Excludes base classes (Agent, MultiAgent)

- **Rust Scanner** (`scripts/parity/scanners/rust_scanner.py`)
  - Regex-based: `pub struct FooAgent`
  - Filters test utilities

- **C++ Scanner** (`scripts/parity/scanners/cpp_scanner.py`)
  - Regex-based: `class FooAgent`
  - Scans header files (.hpp)

- **Zig Scanner** (`scripts/parity/scanners/zig_scanner.py`)
  - Regex-based: `pub const FooAgent = struct`
  - Handles Zig naming conventions

### Feature Categories

1. **Patterns**: Agent implementations (e.g., ReActAgent, ParallelAgent)
2. **Middleware**: Decorators (e.g., TimeoutDecorator, RetryDecorator)
3. **LLM Adapters**: LLM integrations (e.g., OpenAIAdapter, AnthropicAdapter)
4. **Memory**: Memory backends (e.g., InMemoryMemory, VectorMemory)
5. **Techniques**: Advanced techniques (future)

### Reports

**feature-manifest.json**
- Machine-readable feature inventory
- Generated by `feature_scanner.py`
- Used by matrix generator and regression checker

**FEATURE_MATRIX.md**
- Visual parity matrix with ✅/❌ indicators
- Summary statistics and parity percentages
- Test coverage counts

**GAPS_ANALYSIS.md**
- Lists missing features per language
- Compares against Python baseline
- Prioritizes gaps by category

### Critical Features

All languages must implement:
- **Patterns**: Autonomous, Conversational, ReAct agents
- **Middleware**: Timeout, Retry decorators

These checks use case-insensitive substring matching to handle naming variations across languages (e.g., `TimeoutDecorator` vs `TimeoutMiddleware`).

## CI Integration

The GitHub Actions workflow (`.github/workflows/parity-validation.yml`) runs on every PR:

1. Scans all 6 languages
2. Generates parity matrix
3. Runs 45 parity tests
4. Checks for regressions
5. Posts parity summary to PR

**Note**: Local testing with `make test` is the primary validation. CI is supplementary.

## Adding New Features

When adding a feature to any language:

1. **Implement the feature** in your language
2. **Run the scanner** to detect it:
   ```bash
   python scripts/parity/feature_scanner.py
   ```
3. **Regenerate reports**:
   ```bash
   python scripts/parity/matrix_generator.py
   ```
4. **Verify parity**:
   ```bash
   python scripts/parity/check_regression.py
   pytest tests/parity/ -v
   ```

The scanner will automatically detect new features based on naming conventions.

## Troubleshooting

### Scanner Not Detecting Feature

Check naming conventions:
- Python: `class FooAgent`, `class FooDecorator`
- Go: `type FooAgent struct`
- TypeScript: `class FooAgent`, `export class FooAgent`
- Rust: `pub struct FooAgent`
- C++: `class FooAgent`
- Zig: `pub const FooAgent = struct`

### False Positives

Scanners filter out:
- Private types (starting with `_`)
- Mock/test types (`mock` in name)
- Base classes (`Agent`, `MultiAgent`)
- Test utilities (`DummyAgent`, `NoConfidenceAgent`)

If a false positive appears, update the scanner's filter list.

### Regression Check Failing

1. Check which language regressed:
   ```bash
   python scripts/parity/check_regression.py
   ```
2. Review gap analysis:
   ```bash
   cat docs/parity/GAPS_ANALYSIS.md
   ```
3. Implement missing features or update minimums
